# Вопросы, возникшие при реализации

Этот файл накапливает только реальные продуктовые развилки, обнаруженные во время разработки. Они не заменяют закрытый исходный опросник в `17-open-questions.md`. Ответы будут разнесены по модели, API, этапам и UX-документам после основного цикла разработки либо раньше, если вопрос станет блокирующим.

## Проверка письменных решений

1. Должен ли преподаватель или администратор уметь исправить работу, которую школьник по ошибке приложил к другой задаче? Если да, переносится одна выбранная фотография или вся посылка; допустимо ли исправление после завершённой проверки; кто имеет это право и как исходная и новая привязки должны отображаться школьнику в истории?

### Объединённая проверка синонимичных задач

2. Если в одном объединённом кейсе есть несколько посылок в разные синонимичные задачи, какую из них считать последней для записи вердикта: последнюю по времени приёма сервером, по клиентскому времени создания или по другому правилу? Как разрешать совпадение времени?

### Инструменты аннотации

3. Какие инструменты должны войти в первую версию разметки фотографии: только карандаш, ластик, поворот и масштаб или также текст, стрелки, выделение и прямоугольники? Должны ли масштаб и положение холста сохраняться вместе с учительской аннотацией либо оставаться локальным состоянием просмотрщика?

## Исторические данные доступа

4. В миграции `0038` обнаружены похожие на действующие данные доступа, которые нельзя переносить в fixtures, отчёты или новый web-вход. Остались ли они действующими и можем ли мы перед запуском web-аутентификации удалить их из актуального дерева репозитория и выполнить ротацию? Отдельно понадобится решить, требуется ли чистка истории Git или достаточно ротации и последующей migration без секретов.

5. Старый classroom pipeline передаёт `users.token` как `IDd`, а затем использует `IDd` при создании штрихкода на печатных кондуитах. Можно ли из этого штрихкода восстановить тот же Telegram-токен, который станет паролем PWA, и раздавались или сохранялись ли такие листы? Если да, перед web-входом нужно считать соответствующие токены раскрытыми и ротировать их; новый print pipeline в любом случае будет использовать отдельный несекретный public ID.

## Журналы событий

6. В отслеживаемых Git файлах `logs/selected.jsonl` и `logs/cnt.py` есть настоящие идентификаторы, а во втором также имена, использованные при отборе событий. Можно ли оставить эти файлы и их историю в закрытом репозитории или их нужно обезличить и удалить исходные версии из истории Git?

## Внешний недельный pipeline

### Можно ли подготовить обезличенный комплект?

### Какие скрипты используются сейчас?

В описании процесса названы `a15_print_per_aud_conds_html.py`, `a21_create_mails.py` и `a22_mark_compl_in_html_new.py`, а в переданном snapshot соответствующие функции находятся в `a13_print_per_aud_conds_tex.py`, `a22_create_mails.py` и `a23_mark_compl_in_html.py`.

### Как сейчас устроены резервные копии?

## Тестовый Telegram-канал

### Где взять канонический ID тестового канала?

11. Где можно получить канонический отрицательный `chat.id` приватного канала `vmsh179devbot channel`, возвращённый Bot API? У тестового бота включён webhook, поэтому `getUpdates` недоступен, а показанный Telegram UI идентификатор `3913815635` метод `getChat` напрямую не принимает. Нужен сам `chat.id` из сохранённого `channel_post` update либо место, где такой update можно безопасно прочитать; вручную добавлять `-100` мы не будем.
