# Lesson statistics and a53 iteration

Staff student selection uses `apps/staff/src/statistics-student-search.tsx`:
local name search reuses the directory typo-tolerant matcher (case/ё insensitive,
arbitrary word order). Render at most 20 results, request a narrower query for
larger matches. Typing does not fetch charts; selection changes the existing
student URL filter. Native result buttons support Tab/Enter and selection can
be cleared. Covered by `statistics-student-search.test.tsx`, including 2000 names.

Implemented 2026-09-07. Approved scope: live lesson tables count
current scores (1 / 0.5), actual submitters per group including zero scores and
lesson zero. `db_methods/pwa/lesson_statistics.py` reads published membership and
current results; `models/pwa/lesson_statistics.py` aggregates without synonyms.

The course maintenance job performs one a53 iteration for lessons >= 1,
persist current state and publish personal metrics atomically. Graphs are shared
by Staff and personal Student/Family progress. No rankings or cross-course joins.

## API and data rules

`GET /staff/api/v1/statistics` retains the scoped course/group catalog and model
aggregates. Optional `lessonNumber` selects `basicLesson`, with `lessonNumbers`
listing published lessons. Optional `studentId` selects `personal`; `students`
contains current participants within the permitted groups. Course/group and
student authorization is applied before personal metrics are returned.

The live table uses distinct submitters, current 0/0.5/1 credit, and pending
written submissions (not comments, attachments or drafts). It includes zero-score
participants, excludes deleted users and omitted/non-published task membership,
and does not transfer credit between groups through synonyms.
For Student test pairs with PWA attempts, `test_attempts` is authoritative, not
the append-only historical `results` generated by rechecks; other test pairs and
written/oral results use current `results` verdicts. Malformed non-attempts do not
count. Pending checks count as submissions but not model-training observations.

`models/pwa/iterative_analytics.py` preserves one legacy NumPy calc iteration:
select a directly attempted level, distinguish absence from zero, update two
strengths and two difficulties, then build lesson and ±3-lesson pooled ratios.
Only active synonym links within the course lesson identify shared problems.
All current facts are reread on every run, including corrected old attempts.
No previous model is required: new values start at 0.5. Empty denominators keep
the previous value. Internal strengths/difficulties are 0–1, chart strengths 0–10.

Migration `0084.pwa_iterative_analytics` stores current course-scoped state and
smooth metric columns. `db_methods/pwa/iterative_analytics.py` commits state,
metrics and diagnostics together, keeping two completed `a53-iterative` runs per
course. A short read snapshot precedes CPU calculation outside a write transaction.
Existing achievement updates remain separate and commit per student.

## Server rollout

1. Apply migration 0084 through the normal PWA migration/deploy process; update
   backend and all three frontend builds.
2. Install the units from the repository root:

   ```sh
   sudo install -m 0644 vmshpwa/deploy/systemd/vmsh-analytics.service /etc/systemd/system/vmsh-analytics.service
   sudo install -m 0644 vmshpwa/deploy/systemd/vmsh-analytics.timer /etc/systemd/system/vmsh-analytics.timer
   sudo systemctl daemon-reload
   sudo systemctl start vmsh-analytics.service
   sudo journalctl -u vmsh-analytics.service -n 100 --no-pager
   sudo systemctl enable --now vmsh-analytics.timer
   ```

The service uses the same production JSON config and transport environment file
as vmshpwa, with no new secrets. Its write allowlist covers the standard repo
`db` directory; if the configured `db_filename` is elsewhere, adjust
`ReadWritePaths` to that actual directory before installation. The account must
be able to create the adjacent `.analytics.lock` file. The lock also protects
manual CLI runs. The timer runs every even Moscow hour and catches up once after
downtime. Manual rerun: `sudo systemctl start vmsh-analytics.service`.

Logs contain course ID, duration, number of students/problems, max change and
skipped denominator counts, not answers. Failures retain the previous published
model. To stop scheduling: `sudo systemctl disable --now vmsh-analytics.timer`.
No production units or databases were modified by local verification.
