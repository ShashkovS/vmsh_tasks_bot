# Совместимость ответов API с открытыми вкладками

## Требование

Добавление полей в существующий JSON-ответ не требует одновременного обновления
Student, Family и Staff. Объекты ответов, включая вложенные объекты, элементы
массивов, условия и аннотации, игнорируют незнакомые поля. Zod удаляет их из
разобранного значения (`.strip()`), а не передаёт дальше через `passthrough`.

Известные поля по-прежнему проверяются: обязательность, типы, форматы, границы,
дискриминаторы, версии и предметные ограничения. Новый вариант enum или тип
блока документа не равнозначен новому полю; такие изменения требуют отдельного
плана совместимости. Ограничения размера и глубины документов сохраняются.

Конверты исходящих запросов и query-параметры остаются строгими. Общие вложенные
модели, используемые и в ответах, и в запросах, удаляют неизвестные поля перед
отправкой. Серверная валидация запросов и авторизация не меняются. Защиту от
утечки данных обеспечивает серверная проекция, не отклонение ответа браузером.

## Реализация и регрессия

- `packages/contracts/src/*.ts`: модели ответов используют `.strip()` на всех
  уровнях; `.strict()` остаётся у входных команд/запросов и тестовых конвертов.
- `packages/contracts/src/response-compatibility.test.ts`: добавление метаданных
  во все уровни реальных fixtures трёх кабинетов, листков, письменной переписки,
  рекурсивного документа и истории серии; повреждённые известные поля отвергаются.
- `packages/app-shell/src/review-queue-client.test.ts`: чтение условия и предыдущей
  проверки через настоящий HTTP-клиент при дополнительных полях сервера.
- Тесты каталога аудиторий, сводки Staff, импорта, новостей и синонимов проверяют
  удаление новых полей вместо прежнего ожидаемого отказа.
