# Учёт работы преподавателей

Владелец согласовал реализацию 9 октября 2026. Ветка
`codex/teacher-work-accounting` создана от свежей `origin/vmshpwa` (`3af9ffb0`).
Это дополнение существующего Staff: `/staff/users`, вкладка «Учёт работы»,
внутри «Отчёт», «Очные смены», «Zoom», «Настройки». Весь раздел admin-only.

## Источники и правила

- Единственный ledger письменной работы — `results`, `res_type=2`, реальные
  ученики, преподаватель задан, курс через группу задачи. `submission_reviews`
  даёт provenance; AI исключён, повторные человеческие проверки включены.
  Время относится к номеру занятия задачи. Оценка отдельно по `(problem_id,
verdict_id)`: последовательность каждого преподавателя, UTC, `total_seconds`;
  интервалы 1–300 секунд, статистика только меньше 600 секунд, верхняя граница
  `mean + 3 population σ`, ограниченная 60–300. Медиана допустимых интервалов;
  замена с добавкой 4 секунды, без выборки 30 секунд. Исторические результаты
  и их `check_time_spent_sec` не переписываются.
- Zoom: алиасы в пределах курса/сезона, casefold/пробелы/ё/е; исходные подписи
  сохранены. Только текущие teacher/admin, старые numeric IDs не импортируются.
  joined/left паруются по participant ID, непрерывно, с объединением устройств
  и разбиением по местной полуночи. Waiting/breakout не добавляют присутствие.
  При неполном/неоднозначном логе оценка заменяет весь день:
  `min(3.5, max(span_Zoom_results_hours + 0.3, count_Zoom_results / 14))`.
  Только `res_type=3`. Без этих результатов время неизвестно.
- Очные смены: парсинг вставленного сообщения с предварительным просмотром,
  подтверждаемое сопоставление, отдельное сохранение черновика. Комментарии,
  резерв, время и исходный текст сохранены. Одна смена преподавателя на событие,
  комнаты объединяются; неоднозначность времени требует исправления.
  Норма 2.3 часа; границы — из `in_person_events` по календарю портала.
  Отклонение: `max(0, norm + actual_duration - standard_duration)`.
  Норма/границы фиксируются при подтверждении; настройки не меняют прошлые смены.
- Любое время можно заменить абсолютным значением с обязательным комментарием.
  Ручное значение переживает пересчёт; при изменении исходного fingerprint
  показывается «Требует повторной проверки». Аудит actor/time/before/after,
  optimistic version и idempotency.

## Отчёт

Активный курс по умолчанию, диапазон реальных номеров занятий, поиск учителя,
сортировка по общим часам. Приём относится к фактической дате, письменная
работа — к занятию задачи; общие Zoom-окна не дублируются между занятиями.
В таблице и подробностях видны «По логу», «По серии», «Оценка», «Вручную».
Количество: очно/Zoom — дни, письменно — занятия. Сначала сумма, затем округление.

TSV: 13 неизменных metadata columns, три строки заголовка, блоки
«Шк / Пн / Вт / Ср / ✏» с дополнительными фактическими днями Zoom при наличии.
Номера занятий и даты из портала. Часы — одна цифра после точки, общий итог —
две; неизвестное время пустое, отсутствие работы `0.0`.

## Пересчёт и совместимость

Кнопка администратора и существующий `vmsh-analytics.timer` каждые два часа,
единый `.analytics.lock`. CPU вне write transaction, согласованный source
snapshot, атомарная публикация последнего успешного снимка, durable операции.
Ошибка сохраняет последний отчёт. Хранятся два полных derived snapshot;
метаданные операций, idempotency receipts и аудит остаются бессрочно. Очередь
восстанавливается при startup, coalesced запросы сохраняют свои ключи. Правки алиасов/смен/настроек сохраняются сразу; расчёт запускается
отдельной кнопкой или штатным таймером. Telegram, Zoom webhook/queue и прежний математический расчёт сохраняются.
Тесты используют только agent/test runtime без production/Google/Telegram creds.

## Выпуск и проверка на обоих порталах

Новых секретов или зависимостей нет. Штатный deploy должен сделать свежий
SQLite backup, применить 0118 и обновить API/Staff вместе. Репетиционный
backup не использовать вместо актуального. После ввода новых смен и алиасов
при откате адаптера сохранять ту же 0118 в compatible source: down или замена
БД старой копией удаляет новые данные. На TLF рабочие снимки уже рассчитаны;
на ВМШ первый live snapshot — по кнопке или очередному analytics timer.

1. Под admin открыть `/staff/users?tab=work`, выбрать активный курс и пересчитать.
   Проверить письменные часы и подробности нескольких проверок; историческое
   `results.check_time_spent_sec` остаётся прежним.
2. В Zoom подтвердить соответствия текущим преподавателям, игнорировать
   посторонние подписи, сверить парные входы/выходы и оценки неполных дней.
3. Вставить распределение из оргчата, сверить событие, преподавателей, часы и
   исключения «с/до», сохранить черновик, затем подтвердить фактические смены.
   Предварительное распределение включать в отчёт только после подтверждения.
4. Задать ручные часы с причиной, пересчитать, проверить сохранность поправки
   и возврат расчётного времени. Скопировать TSV в рабочую таблицу.
5. Проверить запрет доступа обычному teacher и следующий автоматический
   пересчёт штатного analytics timer. Telegram и Zoom webhook продолжают работать.

## Исправление ввода 12 октября 2026

Сопоставление Zoom — одна versioned/idempotent запись и аудит. HTTP command
не запускает расчёт; каноническая квитанция обновляет все эквивалентные подписи
в query cache без повторного чтения inputs/catalog/report. Чтение inputs
и roster-preview не загружает ledger результатов: отдельные read projections
в `db_methods/pwa/teacher_work.py`. Реализация: `teacher_work_commands.py`,
`teacher_work_routes.py`, `teacher-work-page.tsx`, `teacher-work-inputs.ts`.

Импорт заранее выбирает единственное точное соответствие фамилии, имени,
полного имени или фамилии с инициалами; регистр, ё/е и пунктуация не мешают.
Учитываются оба порядка legacy-полей имени. Конфликтующие имена/инициалы
не выбираются автоматически. Ранее подтверждённые подписи курса запоминаются;
конфликт подтверждений требует ручного выбора. Опечатки дают только короткие
кликабельные подсказки. Неизвестную подпись можно исключить отдельно или убрать все строки без
совпадений одной кнопкой, исходный текст
сохраняется. Сводка и фильтр показывают строки, которым нужен выбор; финальное
подтверждение применяет весь проверенный состав и исключения времени.
Автовыбор существует только в предварительном просмотре и не пишет смены.
Matcher/parser: `models/pwa/teacher_work.py`; UI: `TeacherWorkRosterView`.
