# Интернационализация интерфейса

Решение — [ADR 0004](../../adr/0004-pwa-internationalization.md), фазы и пруфы — [24-i18n.md](../dev/development-plan/24-i18n.md), термины — [глоссарий](i18n-glossary.md).

Исходный язык — русский: текст пишется по-русски прямо в коде, внутри макросов Lingui, и сам служит ключом перевода. Английский живёт в каталогах `.po`. По умолчанию у всех русский; язык выбирается в кабинете и хранится в аккаунте, а cookie `vmsh-locale` запоминает выбор устройства для экранов до входа и для сервера.

## Где что лежит

| Что                                            | Где                                                                                                                                                             |

## Как писать текст во frontend

```tsx
import { t } from '@lingui/core/macro'
import { Plural, Trans } from '@lingui/react/macro'

function Enrollment({ saving, count, name }: Props) {
  return (
    <>
      <h2>
        <Trans>Активная группа</Trans>
      </h2>
      <p>
        <Trans>
          Здравствуйте, {name}! Откройте <a href="/student/profile">профиль</a>.
        </Trans>
      </p>
      <Plural value={count} one="# задача" few="# задачи" many="# задач" other="# задачи" />
      <Button aria-label={t`Сохранить изменения`}>{saving ? t`Сохраняем…` : t`Изменить`}</Button>
    </>
  )
}
```

- Текст в JSX — `<Trans>`; атрибуты и строки — `t` из `@lingui/core/macro`. При смене языка страница перезагружается (сохранение в аккаунт → cookie → reload), поэтому глобальный `i18n` всегда активен на нужном языке и хуки не нужны.
- Массово обернуть файлы: `node scripts/i18n-codemod.mjs <files>` (JSX → `<Trans>`, строки → `t`, модульные свойства → геттеры, `toLocale*String('ru-RU')` → `formatDate`/`formatDateTime`/`formatNumber`); отчёт `MANUAL` разбирается руками.
- Переменные — только простые идентификаторы внутри сообщения: `{name}`. Сложное выражение вынесите в переменную заранее (`lingui/no-expression-in-message`).
- Русские формы множественного числа — `one` / `few` / `many` / `other` через `<Plural>` или `plural()`. Самописные плюрализаторы не нужны.
- Модульные константы (карты статусов, навигация) хранят дескрипторы `msg`, а переводятся при рендере:

  ```ts
  import { msg } from '@lingui/core/macro'
  const statusLabels = { pending: msg`На проверке`, done: msg`Проверено` }
  // в компоненте: const { i18n } = useLingui(); i18n._(statusLabels[status])
  ```

- Вне React (ошибки, `confirm`, парсеры) — `t` из `@lingui/core/macro`, только внутри функции (`lingui/t-call-in-function`).
- Одинаковое русское слово с разными переводами разделяется `context`: `t({ message: 'Проверка', context: 'навигация' })`. Для неоднозначных строк добавьте `comment` для переводчика.
- Названия языков в переключателе не переводятся (`LOCALE_NATIVE_NAMES`).

## Что не переводится

Данные и контент остаются как есть: условия и контент уроков, новости, названия курсов и групп (включая «Начинающие»), имена, комментарии, значения ответов («пн»), названия листов и колонок XLSX/TSV, JSON-ключи legacy print. Если такая строка попала в переведённую область, отметьте её `// eslint-disable-next-line lingui/no-unlocalized-strings -- <почему это данные>`.

Сортировка русских имён и нормализация поиска всегда используют `'ru'` (`localeCompare(…, 'ru')`, `toLocaleLowerCase('ru')`), независимо от языка интерфейса.

## Даты, числа, время

Используйте `useFormatters()` (в компонентах) или `dateTimeFormat(locale, options)` / `numberFormat(...)` (вне React) из `@vmsh/i18n`. Форматтеры кешируются: не вызывайте `toLocaleString('ru-RU')` и не создавайте `new Intl.*` на каждый рендер — в длинных списках это заметно медленно. Бизнес-таймзона (`Europe/Moscow`) передаётся в options, как раньше; меняется только язык. Английский форматируется как `en-US` (решение владельца 19 сентября 2026): месяц перед днём, 12-часовое время.

## Каталоги

1. Написали или изменили текст → `make pwa-i18n-extract`.
2. Переведите пустые `msgstr` в `en.po` (frontend) и `helpers/pwa/locales/en.po` (backend) по глоссарию. `ru.po` генерируется и вручную не правится.
3. `make pwa-i18n-check` проверяет синхронность каталогов, английский для всех сообщений из `i18n-scopes.json` и то, что каждое приложение сливает каталоги всех своих `@vmsh/*` пакетов.

Изменение русского текста создаёт новый ключ, и английский нужно перевести заново — так и задумано. Production-сборка падает, если сообщение из кода отсутствует в каталогах приложения.

## Тесты и Storybook

- Unit-тесты рендерят на русском: `dev/test-support/i18n-setup.ts` активирует `ru` и заранее загружает `en`. Компоненты с `<Trans>` / `useLingui` рендерите через `renderWithI18n` из `@vmsh/test-utils/i18n`. Английский в тесте — `await activateLocale('en', …)` или `changeLocale` из `useLocale()`.
- Storybook рендерит на русском; глобал «Язык интерфейса» в тулбаре переключает всё полотно на английский для просмотра.
- E2E работают на русском; английские сценарии живут в `e2e/i18n.spec.ts`.

## Backend

```python
from apps.pwa_api.errors import PwaApiError
from helpers.pwa.i18n import N_, _, translate

raise PwaApiError(status=409, code="already_reviewed",
                  message="Задача {number} уже проверена", params={"number": number})

DEFAULT_LABEL = N_("Без названия")            # модульная константа: только метка
title = _(DEFAULT_LABEL)                       # перевод на язык текущего запроса
push_title = translate(recipient_locale, N_("Проверка завершена"))  # язык получателя
```

- `pwa_error_middleware` переводит любое `PwaApiError.message` на язык cookie запроса, поэтому русский литерал в `message=` уже является ключом.
- Изменяемые значения передаются через `params` и подставляются как `{name}`; f-строки и конкатенация в сообщении не совпадут с ключом (`make pwa-i18n-check` запрещает их в переведённых областях).
- Тексты для другого получателя (Web Push) переводятся явным `translate(locale, …)` с языком из аккаунта получателя.

## Производительность

- Каталоги компилируются при сборке; в браузере сообщения не разбираются.
- Каталог по умолчанию загружается параллельно с entry (`modulepreload`), PWA кладут оба каталога в precache.
- В горячих списках вычисляйте строки один раз на строку списка, не рендерите `<Trans>` в каждой ячейке.
- После фазы сравните `node scripts/bundle-report.mjs` и `node scripts/startup-benchmark.mjs` с baseline в [отчёте](../dev/i18n-performance-report.md).
