# Итог письменной и Zoom/очной проверки

Решение владельца от 3 октября 2026. Заменяет безусловный приоритет ручной
оценки из `live-marking.md` для сравнения с письменными проверками.

## Контракт

Для ученика и логической задачи (включая подтверждённые синонимы) берутся
последний письменный вердикт и последняя действующая Zoom/очная оценка.
Порядок сохранения — `results.id`, значения — `verdicts.val`.
Более поздняя ручная оценка побеждает всегда. Более ранняя побеждает только
при строго большем значении; при равенстве побеждает письменная.
Письменная перепроверка заменяет текущий письменный вердикт, включая понижение.
Каждый клик приёма создаёт новую оценку; отдельного редактора старой устной
оценки не добавляется. Undo восстанавливает прежний действующий результат.

Старая ручная фиксация сохраняется, даже если письменный результат победил:
после следующей письменной перепроверки сравнение выполняется заново.
История, авторы и исходные задачи не переписываются. Правила автоматических
тестовых ответов из migration 0091/0095 сохраняются.

## Исполнение и приёмка

Общая SQLite-проекция: `migrations/0110.pwa_written_result_precedence.sql`;
потребители — `db_methods/pwa/{content,progress,live_marking,student_results}.py`
и `db_methods/db_results.py`. Complete/коррекция, Telegram teacher handlers
и прежний oral API добавляют новые оценки без обнуления прежних. История и
календарь активности читаются из ledger отдельно от текущего зачёта. Версии
синонимов защищают старые операции от перезаписи нового результата. Public API
и интерфейс проверки сохраняются.

Проверки: старый ручной минус → письменный плюс; старый ручной плюс → письменный
минус; письменный плюс → новый ручной минус; вся шкала и равенства; повышение
и понижение при перепроверке; синонимы, разные учителя, undo, CAS и replay.
Student/Family проверяются без reload, после reload/reconnect. Миграция —
up/down/up, ledger/pointers неизменны, integrity и performance guard проходят.
