# Учительский кабинет и тестирование задач

Требование владельца, 9 сентября 2026: учителям нужны ученические занятия,
сдача тестов и письменных работ с полным циклом проверки; отправки исключены
из общей статистики. Администраторы сохраняют загрузку и тоже тестируют.
Курсы учителя ограничены назначениями; новости отображаются как школьнику;
заглушка устного приёма скрыта.

Реализация: отдельная привязанная к Staff тестовая ученическая
идентичность, реальный Student UI и существующий цикл сдачи/проверки. Это не
вход под чужим школьником. Тестовая личность не имеет выдаваемого пароля;
вход возможен только из авторизованного Staff. На каждом запросе проверяются
состояние владельца и актуальность назначенных курсов/групп. При отзыве прав
старый тестовый доступ закрывается; повторный вход синхронизирует назначения.

Отдельный тип пользователя исключает тестовые отправки из статистики и
каталога школьников. Имя в очереди явно содержит «Тест учителя». Перед входом
пользователь предупреждён, что заменяется Student-сессия этого браузера;
Staff-сессия остаётся отдельной. В Student видна пометка режима и возврат в Staff.
Перед переключением нужно завершить отправки и закрыть остальные Student-вкладки;
для параллельной проверки под настоящим школьником используйте другой профиль браузера.

Проверки: права учителя/админа, запрет школьнику, отзыв прав, повторный вход,
тестовый ответ → результат, фото → очередь → вердикт → исправление,
невключение в статистику/силу, ученическая новостная лента, навигация Staff.
Миграция и frontend/backend должны выпускаться совместно.

## Реализация и выпуск

### Локализация подписи тестового аккаунта — 1 октября 2026

Сохранённое имя тестовой личности содержит служебный русский префикс.
`apps/pwa_api/auth_routes.py::_principal_payload` переводит только эту подпись
для подтверждённого Student типа 512 через `helpers/pwa/locales/en.po`:
«Тест учителя: {name}» / «Teacher test: {name}». Язык берётся из текущего
запроса; существующая сессия получает перевод при обновлении страницы.
Имя учителя и сохранённая запись остаются прежними; миграция не нужна.
`pwa_tests/integration/test_staff_testing_http.py` проверяет English/Russian
для одной сессии учителя и администратора вместе с повторным входом и отзывом
доступа. Все 6 HTTP-сценариев, Ruff и синхронность/покрытие каталогов проходят.
Выпуск завершён: `23c0a65451a55516aaa8ad2e87ed00ce69a009c4` на обоих серверах.
VMSH webhook подтвердил backend-only deploy без миграций; PWA и Telegram active.
TLF SSH release `tlfprep-20261001-teacher-label-23c0a65451a5-r2` прошёл 25
публичных read-only HTTP checks, health и сравнение всех product rows с
остановленными writers. Credentials и NATS PID сохранились. Backup до/после:
`20261001T143017.592484Z` / `20261001T143047.564200Z`, оба integrity=ok.
Первая подготовка остановилась до cutover из-за имени файла data-check;
исправленный скрипт и обе записи выпуска сохранены на сервере.

В штатном тестовом входе администратора проверена реальная страница
`https://prep.leaders.tech/student/tasks?course=math`: шапка показывает
«Teacher test: Administrator TLF Prep Clubs». Ответы и фото не отправлялись.
Снимок: `.runtime/vmshpwa/teacher-label-proof/tlf-success.jpg`.

- `migrations/0085.pwa_staff_testing.sql`: связь Staff account → тестовый user
  типа `STAFF_TEST_STUDENT` (512). История отправок остаётся в обычных таблицах.
- `db_methods/pwa/staff_testing.py` и `apps/pwa_api/auth_routes.py`: список
  доступных курсов и явный POST создания Student-сессии. Пароль не выдаётся;
  login lookup исключает `provisioning_source=staff_testing`.
- `db_methods/pwa/auth.py`: повторная проверка владельца и grant scope на
  каждом запросе, включая refresh и проверку WebSocket-сессии.
- `apps/staff/src/staff-testing-page.tsx`: учителям доступен из «Уроки»,
  «Курсы», «Новости»; администраторам — отдельный `/staff/testing`.
  После подтверждения используется существующее приложение `/student/`.
  Действуют обычные публикации, сроки сдачи и проверяющие; это не preview
  неопубликованного контента и не обход дедлайна.
- `db_methods/pwa/lesson_statistics.py`: текущие факты и расчёт силы допускают
  только настоящих школьников; `course_catalog.py` отдельно исключает тестовые
  аккаунты из количества участников. Операционная очередь включает их,
  поскольку работы действительно требуется проверять.
- `pwa_tests/integration/test_staff_testing_http.py`: настоящий HTTP цикл,
  область доступа, отзыв, новости, тесты/фото/вердикт/correction, статистика.
- `apps/staff/src/staff-testing-page.test.tsx`: список, явный вход, предупреждение,
  пустые назначения и ошибка с повтором. Visual snapshots не обновлялись;
  визуальное принятие владельцем не подразумевается.

Деплой: штатный webhook с backup → migration → backend/frontend → restart.
Новых переменных окружения и сервисов нет. Rollback схемы удаляет только связь,
не уничтожая тестовые работы; для отката кода предпочтителен backup перед
миграцией, если требуется полностью вернуться к прежней схеме.
