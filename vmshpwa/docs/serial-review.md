# Серийная проверка письменных работ

Staff `/review` по умолчанию показывает задачи, упорядоченные по самой старой
посылке. `review-series-model.ts` собирает все страницы разрешённой сервером
очереди, объединяет работы по problem ID и сохраняет отдельный режим всех работ.

`review-series-page.tsx`, маршрут `/review/series/$problemId`, держит не больше
двух захватов: текущую работу и следующую. Следующая заранее монтируется вместе
с фотографиями; её форма и горячие клавиши отключены. После успешного сохранения
текущая удаляется, подготовленная показывается без размонтирования. Завершение
не ждёт обновления списка очереди (`useCompleteReviewMutation`).

Выбор перемешивает пять старейших свободных работ, уменьшая столкновения учителей.
Авторитетным остаётся существующий атомарный claim API: конфликт 409 пропускается,
нельзя отправить вердикт без захвата. Уход из серии освобождает оба захвата;
при закрытии браузера, потере сети или падении процесса действует срок lease.
Предзагрузка резервирует лишь одну дополнительную работу, не весь список.

`ReviewFeedbackForm`: цифры выбирают оценку; Cmd/Ctrl+Enter отправляет её, включая
фокус в комментарии. Незачёт без объяснения сохраняет существующее подтверждение;
повтор комбинации подтверждает отправку. Удержание клавиши не повторяет отправку.
Cmd/Ctrl+Alt+Right пропускает работу; Left открывает предыдущую для исправления
оценки и комментария через существующий идемпотентный correction API. Предыдущая
работа доступна в памяти до выхода из серии. Пометки на фото при этом сохраняются,
исправление не редактирует их. Действия отключены во время сохранения.

`ThreePaneReview` теперь использует полную ширину: короткий перечень веток над
перепиской вместо пустой боковой колонки. Общий компонент проверяется в
`review.stories.tsx`, клавиатурное поведение — в `review-feedback-form.test.tsx`,
выбор и пагинация — в `review-series-model.test.ts`.
