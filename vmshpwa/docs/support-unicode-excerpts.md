# Unicode в превью вопросов — 16 сентября 2026

## Требование и причина

Список вопросов Student/Staff должен принимать превью до 280 Unicode code points,
как `substr(text, 1, 280)` в [support.py](../../db_methods/pwa/support.py).
UTF-16 length в JavaScript считает символы вне BMP (в частности эмодзи) за две
единицы. Прежний Zod max(280) отклонял корректный ответ целиком.
Read-only проверка production обнаружила одно такое превью: 280 code points,
281 UTF-16 единица; последний автор — admin. Поэтому ломались фильтры
«Ждём школьника» и «Все». Текст и история в БД не изменялись.
Два элемента из присланного примера сами по себе не превышают лимит.

## Реализация и проверка

[supportThreadSummarySchema](../packages/contracts/src/support.ts) считает
code points через Array.from. Ограничение 280 сохранено, лишние символы не
обрезаются на клиенте. UI и серверные права не меняются.
[Контрактные тесты](../packages/contracts/src/support.test.ts) проверяют
кириллицу, эмодзи, null и отказ для 281 символа.
[Клиентские тесты](../packages/app-shell/src/support-client.test.ts) загружают
ответ администратора с эмодзи и следующую страницу в обоих затронутых фильтрах.
11 тестов прошли. Для production требуется выпуск обновлённого frontend;
авторизованный браузерный сценарий пока не проверен.
