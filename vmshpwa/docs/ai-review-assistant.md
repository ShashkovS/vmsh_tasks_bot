# AI-помощник через MCP

Решение владельца от 18 октября 2026. Реализовано и проверено локально; production не обновлялся.
[Release gate и визуальные доказательства](../../pwa_tests/reports/ai-review-assistant-20261018/README.md).

Внешний MCP-клиент выбирает модель и загружает приватные предложения. Backend
не вызывает LLM, не меняет результат, очередь, lease и не отправляет сообщения.
Учитель отдельно добавляет комментарий в конец своего текста и выбирает вердикт.
Разбор модели остаётся Staff-only. Доступны несколько вариантов для одной работы.

Первые поддерживаемые клиенты — локальные stdio MCP (Codex / Claude Code),
обращающиеся по HTTPS к текущему aiohttp backend. Токены личные, отзываемые,
действуют 90 дней и ограничены текущими правами сотрудника. В базе только хеши.

Контекст содержит условия, ответы, неопубликованные решения, полную учебную
переписку, фото учеников и преподавателей, разметку с явным авторством. Личные
контакты и административные заметки исключены. Это заменяет прежние ограничения
AI-контекста и запрет предложения вердикта в product-ux-decisions-2026-07.md.

Только ожидающие работы с материалами Staff PWA принимают предложения.
Старая Telegram-only очередь явно неподдерживаема. Версия контекста включает
материалы, переписку, учебные редакции и результат, но не claim/heartbeat.
Устаревшие варианты сохраняются, их применение недоступно.

## Подключение

1. Откройте Staff → «MCP-доступ», создайте именованный токен и сохраните
   однократно показанный секрет. Каждому клиенту лучше выдать собственный токен.
2. В локальной копии проекта установите зависимости: `uv sync --group mcp`.
3. Задайте в MCP-клиенте команду и окружение (значения в угловых скобках замените):

```json
{
  "command": "uv",
  "args": [
    "--directory",
    "<absolute-path-to-vmsh_tasks_bot>",
    "run",
    "--frozen",
    "--group",
    "mcp",
    "python",
    "-m",
    "ai_review_mcp"
  ],
  "env": {
    "VMSH_AI_REVIEW_URL": "https://<portal-host>",
    "VMSH_AI_REVIEW_TOKEN": "<one-time-token>"
  }
}
```

Это параметры запуска, а не полный файл настроек конкретного клиента. Для
исполняемых файлов вне `PATH` используйте абсолютный путь к `uv`.
Разрешён только HTTPS origin без URL-пути; HTTP допускается исключительно для
loopback при локальной проверке. Клиент отправляет Origin этого же портала;
backend сохраняет общую проверку Host/proxy/origin. stdout содержит только MCP,
диагностика направляется в stderr. SDK находится в группе `mcp`, backend его
не импортирует. SQLite, Telegram и Google локальному процессу не нужны.

Личный токен наследует текущие права Staff без браузерных cookies. Снятие scope,
отзыв токена, изменение credential version и блокировка аккаунта действуют сразу.
Возможности токена не включают выдачу новых токенов, изменение оценок или отправку
сообщений. При отзыве уже сохранённые предложения остаются доступными учителям.
Модель работает на стороне выбранного MCP-клиента; приложение не выбирает тариф
и не обещает доступность конкретной модели в подписке.

## Работа через инструменты

Списки `list_courses`, `list_groups`, `list_lessons`, `list_problems` и
`list_pending_reviews` возвращают по 50 элементов и `nextCursor`. Для очереди
доступны фильтры `course_id`, `group_id`, `lesson_id`, `problem_id`,
`suggestions=any|with|without`. Синонимы дедуплицируются по работе ученика.
`logicalCaseId` старой очереди обозначает задачу и не используется как ID работы.
Работы `supported=false` нельзя передавать в `submit_ai_suggestion`.

## Массовая выгрузка для калибровки

Дополнение владельца от 18 октября: модель должна читать предыдущие комментарии
и сравнивать посылки одной задачи, включая прежние проверенные попытки ученика,
у которого уже появилась новая непроверенная посылка. Реализация:
[read model](../../db_methods/pwa/ai_review_exports.py),
[домен](../../models/pwa/ai_review_exports.py),
[MCP-инструменты](../../ai_review_mcp/server.py),
[HTTP-тесты](../../pwa_tests/integration/test_ai_review_exports_http.py).
Миграций и изменений интерфейса этот инкремент не требует.

- `list_review_comments(lesson_id?, problem_id?, cursor?)` — фактически
  опубликованные преподавательские комментарии, включая Telegram-архив, автора,
  время, вердикт и изображения/разметку. Нужен хотя бы один фильтр; два фильтра
  пересекаются. Комментарий проверки нескольких синонимов выдаётся один раз с
  `problemIds`. AI-предложения и внутренние заметки/реакции сюда не входят.
- `get_problem_submissions(problem_id, status="all", page_size=10, cursor?)` —
  пакет посылок фиксированной задачи. `pending` выбирает непроверенные посылки,
  `reviewed` — посылки с зафиксированной проверкой, `all` — все, включая
  заменённые/перенесённые (`superseded`) и старые сообщения без достоверного
  состояния проверки (`unknown`). Состояние определяется для каждой посылки;
  отсутствие записи в текущей очереди само по себе не означает «проверено».
  Автоматические тестовые попытки также включены. `submissionCounts` содержит
  количества по всем состояниям, `selectedSubmissionCount` — размер выборки.

Каждый элемент пакета — один ученик по одной точной задаче: выбранные посылки,
полный `dialogue` со всеми прежними попытками и комментариями, версии условий,
ответы/решения и идентификаторы изображений. Синонимы задачи не подмешиваются
в список посылок этой задачи. Опубликованные комментарии общей проверки видны
только сотруднику с правами на все ветки этой проверки.

Примеры вызовов MCP:

```text
list_review_comments(lesson_id="gl-1")
list_review_comments(problem_id="p-1")
get_problem_submissions(problem_id="p-1", status="pending")
get_problem_submissions(problem_id="p-1", status="reviewed")
get_problem_submissions(problem_id="p-1", status="all")
```

Комментарии выдаются по 50, пакеты — по 1–20 учеников (по умолчанию 10),
сразу со всей их перепиской, без отдельного запроса на каждого ученика.
Для полной выгрузки нужно следовать `nextCursor`, пока он не станет `null`;
`total` показывает число комментариев или выбранных учеников во всей выборке.
На маленькой группе всё возвращается одним вызовом. При слишком большом
ответе уменьшите `page_size`. Cursor привязан к фильтрам и содержимому выборки:
изменение данных между страницами возвращает `ai_context_changed` (409),
нужно начать выгрузку заново. Каждый HTTP-вызов читает единый SQLite snapshot.

`caseId=history-...` и `snapshot` из выгрузки можно передать в существующие
`get_review_context`, `get_review_dialogue`, `get_review_image`: они доступны
также для старой переписки без современной Staff-посылки. Картинки загружаются
отдельно image-блоками, с той же проверкой прав и версии контекста. Исторический
ID предназначен для чтения. Чтобы предложить новую проверку, нужно прочитать
`get_review_context(suggestionCaseId)` и использовать его актуальный snapshot;
`suggestionCaseId=null` означает, что доступной работы для предложения сейчас нет.

У старых Telegram-сообщений отсутствует связь с evidence конкретной проверки:
они выдаются с `unknown` в режиме `all`, а не получают вымышленный статус по
времени более поздней оценки. Публикации прошлых комментариев это не мешает.

## Предыдущие занятия того же уровня

Дополнение владельца от 18 октября: для согласованной проверки модель получает
условия, подсказки и решения последних 3, 5 или другого числа предыдущих занятий
одним запросом. Реализация: [SQLite](../../db_methods/pwa/ai_review_curriculum.py),
[домен](../../models/pwa/ai_review_curriculum.py),
[MCP](../../ai_review_mcp/server.py),
[HTTP-тесты](../../pwa_tests/integration/test_ai_review_curriculum_http.py).

```text
get_previous_lesson_materials(lesson_id="gl-17", count=3)
get_previous_lesson_materials(lesson_id="gl-17", count=5)
```

`lesson_id` — текущее занятие из `get_review_context` или `list_lessons`.
Уровень определяется группой этого занятия внутри кружка. `count` — целое число
от 1 до 20, по умолчанию 3. Выбираются ближайшие предыдущие занятия со статусом
`active` или `archived` той же группы и кружка по меньшему учебному номеру.
Текущее занятие, последующие номера, черновики занятий и другие уровни исключены.
Пропуски в нумерации допустимы. Внутри ответа занятия идут от старого к новому.
`requestedCount`, `returnedCount`, `availablePreviousCount` явно показывают,
когда история короче запрошенной; первый урок возвращает пустой список.
Порядок занятий и публикация материалов сами по себе не доказывают посещение
или усвоение темы конкретным учеником.

Все выбранные занятия приходят одним ответом без пагинации или лимита задач
внутри листка. Для каждого занятия возвращаются название, полный `materials`
с условиями/подсказками/решениями, вступлениями и ещё не сопоставленными задачами,
связи с каталогом и ответы из этой же редакции, идентификаторы изображений,
`missingMaterials` и отдельный `snapshot` занятия. Внутренние `teacher_note`
в этот пакет не входят. Материалы считаются данными, а не инструкциями модели.

Для каждого источника выбирается текущая опубликованная редакция, если она
существует; иначе — последняя редакция источника с `publicationState=unpublished`.
Так новый приватный черновик не подменяет опубликованное условие. Архивный
источник с действующей публикацией сохраняется рядом с активной приватной
заменой; остальные архивные источники исключены. Неопубликованные подсказки
и решения доступны сотруднику как эталон и явно отличаются от выданного ученикам.
`publishedAt`, `revisionId`, `revisionNumber`, `version` и `status` сохраняются.

Если валидного `web_ast` нет, материал не теряется: `availability=source_only`,
`document=null`, в `latex` находится полный исходный текст. Отсутствующий тип
материалов перечислен в `missingMaterials`; пустое занятие также возвращается.

Для изображения вызовите `get_lesson_material_image(lesson_id, snapshot, image_id)`
с идентификаторами и **snapshot конкретного занятия** из пакета. Инструмент
возвращает MCP image-блок, поддерживает тот же безопасный SVG preview и проверку
целостности, что изображения работ. Произвольные assets недоступны. Права
проверяются заново; при изменении материала/публикации возвращается
`ai_context_changed` (409), после чего нужно перечитать пакет.
Весь пакет читается из единого SQLite snapshot и не зависит от наличия посылок
или очереди проверки по прошлым занятиям. Миграций и изменений UI не требуется.

## Предложение новой проверки

Обычный проход:

1. Выбрать кружок, группу, занятие и ожидающую работу (`caseId`).
2. Получить `get_review_context(case_id)`: immutable evidence, учебные материалы,
   `snapshot`, действующую шкалу и `allowedVerdicts`. Условия привязаны к редакциям
   посылок; ответы доступны даже при отсутствии готового изображения условия.
   Отсутствующие условия/подсказки/решения явно перечислены в `missingMaterials`.
3. Прочитать все страницы `get_review_dialogue(case_id, snapshot, cursor)` и
   нужные `get_review_image(case_id, snapshot, image_id)`. Оригиналы, composite
   преподавательской разметки и рисунки учебных материалов имеют разные image IDs.
   Картинки возвращаются MCP image-блоками; SVG проходит sanitizer и raster preview.
4. Загрузить `submit_ai_suggestion(case_id, snapshot, idempotency_key, source,
comment?, verdict?, analysis?, model?)`. Хотя бы одно из трёх содержательных
   полей обязательно. Текст ограничен 100 000 символов на поле. Вердикты: 11 −,
   12 −·, 13 −+, 14 ½, 15 +−, 16 +·, 17 +; допустимое подмножество возвращает контекст.
5. При `ai_context_changed` перечитать контекст и заново проверить работу.
   `list_ai_suggestions` позволяет увидеть уже загруженные варианты.

Для нового варианта нужен новый `idempotency_key`; повтор прежнего запроса
возвращает прежний ID. Изменение содержимого при прежнем ключе даёт конфликт.
Успешную загрузку можно безопасно повторить и после человеческой проверки;
новый вариант после завершения проверки отклоняется. Названия source/model
задаются загрузившим клиентом и не являются проверенной идентичностью модели.

Условия, ответы, решения и преподавательский разбор могут раскрывать эталон.
Они отделены от предлагаемого комментария ученику. Инструкции MCP требуют
не переносить неопубликованное решение в этот комментарий; финальный текст
проверяет и отправляет преподаватель. Тексты и изображения ученика считаются
учебными данными, а не инструкциями для вызова инструментов.

## Staff и HTTP-контракт

Cookie-only API: `GET/POST /staff/api/v1/ai-review/tokens`,
`DELETE /staff/api/v1/ai-review/tokens/{tokenId}` и
`GET /staff/api/v1/review/ai-suggestions?caseId=...` (либо `queueId=...`).
Token-only bridge: `POST /staff/api/ai-review/v1/tools/{tool}`. Здесь названия
параметров JSON — camelCase; локальные MCP-инструменты используют snake_case.
Общие строгие входные схемы —
[ai_review_contract.py](../../models/pwa/ai_review_contract.py),
Staff Zod-контракты — [ai-review.ts](../packages/contracts/src/ai-review.ts).

[Панель](../apps/staff/src/ai-review-panel.tsx) загружается независимо от
[обычной/серийной проверки](../apps/staff/src/review-workspace-page.tsx) и
[простыни](../apps/staff/src/review-sheet-card.tsx). Новые предложения проверяются
раз в 30 секунд только для активной карточки. Пустая панель не отображается;
ошибка не вызывает глобальный экран недоступности сервиса. Снимок открытой
карточки сверяется с evidence ответа, кнопки устаревших предложений отключены.
Человеческое завершение проверки не импортирует AI-домен и не требует AI-полей.

Просмотр и применение доступны всем Staff с полными правами на связанные ветки
работы. Применение редактирует только существующий локальный черновик.
AI-данные не записываются в submission_entries или results и не сериализуются
в Student/Family/Telegram. Отдельного бейджа «с участием AI» у результата нет.
Новые тексты интерфейса и HTTP-ошибок переведены на английский.

штатным `schema_inventory generate --write`. Отдельные процессы/systemd units,
новые порты и provider credentials для backend не требуются. Production-выкладка
и remote HTTP MCP для веб-клиентов не входят в этот инкремент.
