# Отложенные проверки после потери фотографий

Для случая Beget: убрать непроверяемые работы из активной очереди, сохранив
сами работы и возможность возврата. Пользователь одобрил эту операцию для
8-го занятия 17 ноября 2026. Оценки, статусы сдач и переписка не меняются;
никаких зачётов, отказов или сообщений школьникам операция не создаёт.

В `deferred_review_queue` лежат исходные строки рабочей очереди, причина,
время и снимок версий связанных работ. Это часть основной SQLite и обычного
бэкапа, а не отдельный архив/дамп. Самих ответов и фотографий эта таблица не
копирует. Рабочие позиции из `written_tasks_queue` снимаются одной транзакцией.
Другие занятия и работа без вложений остаются в очереди.

Реализация: [миграция](../../migrations/0124.deferred_review_queue.py),
[SQL операции](../../db_methods/pwa/deferred_reviews.py),

## Использование

На сервере из root-сессии, без подстановки паролей в команды:
Запись в SQLite команда выполняет от владельца БД, чтобы не создавать root-owned
WAL/SHM. Приватный manifest должен быть доступен этому пользователю.

```bash
PY=/web/vmsh_tasks_bot/vmsh_tasks_bot/.venv/bin/python
TOOL=/web/vmsh_tasks_bot/cutover-20261117/tools/deferred_reviews.py
DB=/web/vmsh_tasks_bot/vmsh_tasks_bot/db/production_v2.db
STATE=/web/vmsh_tasks_bot/deferred-review-state
```

План проверяет HEAD всех фотографий в текущем S3; в список попадают только
позиции 8-го занятия, у которых **все** фотографии отсутствуют. Любая ошибка
доступа, отличная от not-found, останавливает операцию. План приватный, 0600.

```bash
"$PY" "$TOOL" plan --database "$DB" --manifest "$STATE/lesson8-plan.json"
"$PY" "$TOOL" hold --database "$DB" --manifest "$STATE/lesson8-plan.json"
"$PY" "$TOOL" list --database "$DB"
```

Batch по умолчанию: `beget-loss-lesson8-20261117`. Перед применением должны быть
установлены модуль и миграция; стандартные schema migrations требуют остановки
writers. Повторный `hold` того же плана ничего не меняет. Если версия работы
изменилась после составления плана, операция откатывается — составить новый.
После применения обновить страницу очереди Staff.

## Когда нашлись файлы

Сначала вернуть оригинальные файлы в S3 с теми же object keys. Затем:

```bash
# Все восстановленные работы batch:
"$PY" "$TOOL" restore --database "$DB"
# Или только конкретная позиция, если нашлись не все файлы:
"$PY" "$TOOL" restore --database "$DB" --queue-id QUEUE_NUMERIC_ID
```

Команда сначала сверяет реальные файлы с исходными SHA-256/размерами. При
отсутствующем или изменённом файле возврата не будет. Новый перекодированный
оригинал с другим хешем требует отдельного восстановления вложения, не подмены
байтов в старой записи.

SQL-операция также не возвращает работу, если появилась новая активная очередь
или изменилась версия/проверка самой сдачи. Это предотвращает повторную проверку
уже оценённого и затирание новой сдачи. Старый lease/teacher claim не восстанавливается:
работа возвращается как новая для взятия любым преподавателем, с прежним временем
поступления. Строка истории в `deferred_review_queue` остаётся с `restored_at`.

## Проверки

Unit-тесты покрывают hold/restore, очистку просроченного захвата, повторный
запуск, откат при искусственной ошибке, изменение сдачи и новую очередь.
До production операция репетируется на временной SQLite Backup API копии;
сверяются FK, integrity и неизменность записей ответов/оценок. Рабочая копия
после проверки удаляется, в бэкапы не добавляется.

## Применено 17 ноября 2026

Проверены 30 S3-объектов: все отсутствуют. Отложены **26 позиций у 16 школьников**.
Одна позиция 8-го занятия без вложений осталась в очереди. Ответы, переписка,
вложения и результаты не редактировались. Репетиция на копии production:
hold 26, повтор 0, restore 26, rollback/FK/integrity — pass; SQLite authorizer
подтвердил запись только в queue и holding table. Временная копия удалена.
На production миграция и применение прошли, backend возобновлён, Staff runtime
отвечает, упавших units нет. Приватный план и отчёт —
`/web/vmsh_tasks_bot/deferred-review-state`; состояние отложения — в основной БД.
Дополнительных архивов/бэкапов для операции не создавалось. Шесть unit-тестов прошли.
