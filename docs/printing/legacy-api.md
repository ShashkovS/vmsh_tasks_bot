# Переходный API распределения для старой печати

Решение владельца от 12 сентября 2026: перед ближайшим занятием заменить
Excel как источник рассадки, сохранив a11–a14 и прежнюю печать. Внешняя папка
не редактируется агентом; ниже точные изменения для переноса вручную.

## Сервер

Реализация: [routes](../../apps/pwa_api/legacy_print_routes.py),
[доменная проверка](../../models/pwa/legacy_print.py),
[чтение логинов](../../db_methods/pwa/legacy_print.py),
[регистрация](../../apps/pwa_app.py), [конфигурация](../../helpers/config.py).
Новых таблиц и миграций нет. Запросы не меняют рассадку, группы или результаты.

В **серверный JSON профиля**, из которого запускается PWA, добавить:

На проверенном production это
`/web/vmsh_tasks_bot/vmsh_tasks_bot/creds_prod/vmsh_bot_config_prod.json`.
Штатный SSH-пользователь `vmshbegetagent` не может писать этот файл;
настройку выполняет владелец или разрешённый deployment с нужными правами.

```json
"legacy_print_api_token": "<отдельный случайный секрет длиной не менее 32 символов>"
```

Например, секрет можно локально получить `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
Это отдельный токен только для чтения печати, не пароль ученика, не Telegram
bot token и не ключ импорта результатов. Поле исключено из `repr(Config)` и
runtime API. Без корректно заданного токена endpoint отвечает 503.
После доставки кода и настройки профиля нужен перезапуск backend workers.
В существующем nginx-шаблоне `/staff/api/` уже проксируется на backend;
новый location для этого API не требуется. Фактический production deployment
должен проверяться отдельно; наличие этих файлов не означает обновления сервера.

Оба GET endpoint требуют заголовок `Authorization: Bearer <секрет>`.
Cookie входа в Staff не заменяет токен; этот токен не открывает обычные Staff API.
Сохраняется проверка допустимого host/proxy/origin, ответы имеют `no-store`.
Секрет не передавать в URL.

```text
GET https://vmsh.shashkovs.ru/staff/api/legacy-print/v1/events
GET https://vmsh.shashkovs.ru/staff/api/legacy-print/v1/events/EVENT_ID/pupils?lesson=4
```

Первый endpoint возвращает до 100 последних неотменённых событий активного сезона:
ID, название, дату, статус, номера прикреплённых занятий и ID/версию
подтверждённого плана, если он есть. Например, в ответе из вопроса `ipe-1` — ID очного события,
а `lessonNumber: 2` — номер занятия. Это разные сущности. Второй endpoint
возвращает **JSON-массив строк напрямую**, соответствующий результату
`parse_xls_conduit`, а не `{pupils: ...}`.

```json
[
  {
    "Фамилия": "Иванов", "Имя": "Иван",
    "ID": "ivanov.ivan", "IDd": "ivanov.ivan",
    "Клс": "7", "Скрыть": null, "Уровень": "н", "Аудитория": "201",
    "Посещаемость": null, "Ср3": "",
    "ФИО": "Иванов Иван", "ФИ.": "Иванов И.", "Строчка": 5,
    "UserID": 123, "GroupID": "н"
  }
]
```

Это вымышленная строка. `ID`/`IDd` — `auth_accounts.username`, **не** старый
`users.token`, который может служить секретом входа. `UserID` — внутренний
`users.id`; `GroupID` — фактический legacy group ID из плана для запросов к problems.
`Уровень` — short_code группы (`н`, `п`, `э`); он может отличаться от GroupID.
`Строчка` — синтетическая нумерация с 5, не адрес строки в реальном workbook.
`Посещаемость` и `Ср3` оставлены пустыми: a11–a14 не требуют вычисления этих
статистик для печати. Регистр имён сохраняется из портала; сортировка учитывает ё=е.

Поддерживается один курс и один номер занятия на событие, как в нынешних скриптах.
Указывать `lesson=cur_les` обязательно. Нельзя случайно получить другой номер.
Export выбирает confirmed plan, проверяет совпадение с текущим составом active
in-person enrollment, комнатами и группами. Если есть рабочий draft/stale plan,
сначала нужно завершить работу с ним и подтвердить его. Строки с ошибками
не пропускаются молча. Имена и назначения читаются в одном SQLite snapshot.

В ответе есть `ETag`, `X-Print-Event`, `X-Print-Lesson`, `X-Print-Plan`,
`X-Print-Plan-Version`. `If-Match: <полученный ETag>` позволяет потребовать
тот же состав/подписи/план: при изменении ответ 412.

Основные ошибки:

| Код HTTP | Действие |
| --- | --- |
| 401 | Проверить отдельный Bearer token |
| 403 | Проверить host/origin/proxy; использовать штатный HTTPS домен |
| 404 | Проверить EVENT_ID и наличие обновлённого backend |
| 409 | Прочитать `error.message`: подтвердить/обновить план, проверить номер, коды групп и логины |
| 412 | Данные изменились относительно `If-Match`; решить, нужен ли новый комплект |
| 422 | Передать один корректный `lesson` |
| 503 | Настроить токен или восстановить доступность БД |

## Что добавить во внешнюю папку

Скопировать [legacy_print_client.py](legacy_print_client.py) рядом с `a11`, `a13`
и `z_helpers.py` **под именем `z_portal_print.py`**. Нужен Python 3.9+, только
стандартная библиотека; устанавливать requests не требуется.

Для ручной диагностики API клиент по-прежнему можно вызвать отдельно. Тогда
токен передаётся через `VMSH_PRINT_API_TOKEN`:

```sh
python z_portal_print.py events
python z_portal_print.py download EVENT_ID 4
```

Для штатной сборки эти команды больше не нужны: `a11` сам вызывает API.

В локальный `z_CREDENTIALS.py`, где старые скрипты уже хранят свои секреты,
добавить:

```python
PORTAL_PRINT_API_TOKEN = 'тот же отдельный секрет, что на сервере'
```

Токен нельзя писать в `z_CONSTS.py`, `z_portal_print.py` или репозиторий.
`z_CONSTS.py` уже делает `from z_CREDENTIALS import *`, а `a11` —
`from z_CONSTS import *`, поэтому дополнительный импорт константы не нужен.

`a11` создаст `portal-print.json` рядом со скриптом, с людьми и метаданными плана,
без токена. Сохранение атомарное: сетевой сбой не оставит обрезанный файл.
Все последующие шаги печати читают **один и тот же снимок**, поэтому сборка не
меняется посередине. Не добавлять этот файл и токен в git.

### a11_spis_from_xls.py

Добавить импорт:

```python
from z_portal_print import refresh_portal_conduit
```

Заменить:

```python
pup_lst = parse_xls_conduit(XLS_CONDUIT_NAME)
```

на:

```python
pup_lst = refresh_portal_conduit(
    cur_les,
    token=PORTAL_PRINT_API_TOKEN,
)
```

Теперь обычный запуск `a11_spis_from_xls.py` сам скачивает свежий confirmed plan,
атомарно обновляет снимок и возвращает готовый `pup_lst`. Сначала клиент получает
`/events` и выбирает единственное событие с подтверждённым планом, у которого
полный набор `lesson_numbers` равен `[cur_les]`. Поэтому еженедельно переносить
`ipe-...` в настройки не нужно.

Если для одного номера найдены ноль или несколько подходящих событий, клиент
завершает работу и показывает найденные ID. Для осознанного выбора можно добавить
в `z_CREDENTIALS.py`, например:

```python
PORTAL_PRINT_EVENT_ID = 'ipe-1'
```

и временно вызвать:

```python
pup_lst = refresh_portal_conduit(
    cur_les,
    token=PORTAL_PRINT_API_TOKEN,
    event_id=PORTAL_PRINT_EVENT_ID,
)
```

Если сеть, токен, событие или план не готовы, a11 завершается до удаления прежних
списков и PDF: вызов остаётся на месте нынешнего `parse_xls_conduit`, выше
`remove_old_spis()`. Отдельные команды `events` и `download` для штатной печати
не нужны.

Остальные фильтры и генерация `spisok`/списков/статистики сохраняются.
Не прогонять новые логины через обрезание цифр или старую нормализацию token.

### z_helpers.py: соответствие логина внутреннему ID для штрихкода

Одной заменой чтения Excel дело не ограничивается: нынешний
`crt_aud_barcode` вызывает `get_num_ids_from_db`, где ключом является `users.token`.
Логин из API в таком словаре не найдётся. Добавить импорт:

```python
from z_portal_print import load_portal_conduit
```

И заменить **только функцию** `get_num_ids_from_db`:

```python
def get_num_ids_from_db(cache=None):
    pupils = load_portal_conduit(cur_les)
    mapping = {pupil['IDd']: pupil['UserID'] for pupil in pupils}
    if any(not 0 < user_id < 10000 for user_id in mapping.values()):
        raise ValueError('UserID не помещается в старый четырёхзначный штрихкод')
    return mapping
```

Несмотря на прежнее имя, функция теперь берёт готовое соответствие из API-снимка.
Остальной Code128/checksum остаётся прежним. Текущий код также преобразует номер
аудитории `int(aud, 36)` и обрезает до четырёх цифр: нестандартные названия комнат
потребуют отдельной правки кодирования, не замены API. Для обычных 201/202/…/316
прежнее кодирование сохраняется.

### a13_print_per_aud_conds_tex.py

Добавить импорт и заменить чтение Excel точно так же, как в a11:

```python
from z_portal_print import load_portal_conduit, get_portal_pupils_for_results

pup_lst = load_portal_conduit(cur_les)
```

Заменить **только функцию** `get_pupils`:

```python
def get_pupils(cur, tokens):
    return get_portal_pupils_for_results(tokens, cur_les)
```

Это сохраняет форму результата, ожидаемую a13: `id`, `token`, `surname`, `name`,
`group_id`, `grade`. Имена, группы и ID берутся из того же плана, что в a11.
Аргумент `cur` оставлен ради совместимости вызова. Сам SQL чтения задач и
результатов остаётся прежним.

**Для a13 всё ещё нужна свежая локальная SQLite того же проекта с теми же
users.id/problems/group_id.** Новый API экспортирует рассадку, а не results.
Если локальная БД относится к другому сезону/перенумерованной копии или новых
задач там нет, одной этой интеграции недостаточно для прошлых результатов.
И прежняя агрегация a13 не становится новой портальной логикой ручных исправлений.

Если используется `SPLIT_LARGE_AUD`, a11 и a13 должны делить комнаты одинаково.
В старом a13 деление отсутствовало; либо оставить `SPLIT_LARGE_AUD = {}`, либо
сразу после загрузки добавить там `change_split_auds(pup_lst)`, как в a11.

### a12 и a14

Замена чтения не нужна: a12 использует сгенерированные списки и учебные материалы,
a14 — PDF и zstats. После download запускать привычную цепочку a11 → a12 → a13 → a14.
Пути к TeX, стилю, картинкам и локальной базе в старой папке не меняются.

Этот снимок не предназначен для обратной записи в Excel по `Строчка` через a18:
реальных номеров строк workbook в нём нет.

## Если нужен именно непосредственный вызов API

Экспорт уже возвращает нужный список. Минимальный вариант с установленным requests:

```python
import os
import requests

def parse_portal_conduit(event_id, lesson):
    response = requests.get(
        f'https://vmsh.shashkovs.ru/staff/api/legacy-print/v1/events/{event_id}/pupils',
        params={'lesson': lesson},
        headers={'Authorization': 'Bearer ' + os.environ['VMSH_PRINT_API_TOKEN']},
        timeout=30,
        allow_redirects=False,
    )
    if response.status_code != 200:
        raise RuntimeError(f'API печати: HTTP {response.status_code}')
    return response.json()
```

Но для согласованной многоскриптовой печати предпочтителен файл одного снимка.
В обоих случаях правки сопоставления ID для штрихкодов и a13 остаются необходимыми.

## Проверка

[HTTP/SQLite tests](../../pwa_tests/integration/test_legacy_print_api.py) проверяют
форму данных, закрытый по умолчанию токен, отсутствие обхода через cookie/query,
сохранение браузерной авторизации, параметры занятия, автоматический и явный выбор
события, ETag и устаревший состав. Итог: 23 профильные проверки прошли, Ruff
прошёл. Production пока не обновлён; подробности и независимое старое падение
classroom suite — в [STATUS.md](STATUS.md).
