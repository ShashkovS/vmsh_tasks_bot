Дата: 30 июля 2026 года.

## Результат

На отдельной копии `db/vmsh.db` выполнены обезличивание, все актуальные
миграции и первый многокурсовый backfill:

- создан сезон `2025-26` и курс `course-math-5-7` «Математика 5–7»;
- четыре существующих `group_id` сохранены и привязаны к курсу;
- для 1 617 школьников созданы course enrollment;
- текущая группа совпала у всех 1 617 школьников;
- режим `online|in_person` совпал у всех 1 617 школьников;
- созданы 4 851 активных интервала доступа к группам;
- прочитаны 5 392 исторические `G/O`-строки учеников;
- 797 первых строк стали восстановимым baseline, 1 881 последовательная
  повторная команда схлопнута как no-op;
- созданы 2 714 восстановимых переходов и 55 явных reconciliation-событий для
  случаев, где последняя legacy-запись не совпадала с текущим `users`;
- 110 legacy group lessons занятий 1–37 привязаны к 37 общим course lessons;
  одинаковый номер в разных группах получил общий course identity;
- три технические строки занятия 0 явно исключены: целевая модель и
  исторический product scope начинаются с занятия 1; отсутствие занятия 36 у
  «Экспертов» сохранено, а не заполнено вымышленной строкой;
- проверены 1 796 legacy-задач и 2 106 ссылок в `problems.synonyms`;
- 1 641 логическая компонента включает 1 486 одиночных задач и 155 пар
  синонимов; все 155 повторяющихся нормализованных названий уже связаны;
- каждая synonym-компонента целиком лежит в одном занятии, содержит не больше
  одной задачи конкретной группы и имеет взаимные полные ссылки;
- исходные problem/result/submission ID и строки `problems.synonyms` не
  изменялись; целевые `problem_synonym_*` ещё не создавались, поскольку для них
  сначала нужны owner-reviewed content/problem revisions;
- `PRAGMA integrity_check`: `ok`.

Агрегированный результат сохранён в
[`phase11-course-enrollment-rehearsal.json`](phase11-course-enrollment-rehearsal.json).
В нём нет имён, дат рождения, Telegram ID или токенов.

## Граница безопасности

[`legacy_course_rehearsal.py`](../../vmshpwa/scripts/legacy_course_rehearsal.py)
открывает исходную SQLite только для чтения через backup API. Новая база может
находиться только внутри `.runtime/phase11-rehearsal` и не должна существовать
до запуска. До применения миграций в копии заменяются имена, фамилии, даты
рождения и токены, а Telegram chat ID очищаются. Исходные строки, legacy ID,
задачи и результаты не изменяются.

Команда для новой одноразовой копии:

```shell
PWA_REHEARSAL_TARGET=.runtime/phase11-rehearsal/<run-id>.sqlite3 \
PWA_REHEARSAL_REPORT=.runtime/phase11-rehearsal/<run-id>.json \
make pwa-phase11-course-rehearsal
```

## Проверки

- unit/integration: исходная БД остаётся неизменной, копия обезличивается,
  legacy group IDs сохраняются, group/mode/access parity совпадает;
- повторный backfill не создаёт дубли;
- история `G/O` сохраняет исходный порядок, не превращает повторную команду в
  переход и заканчивается текущими group/mode каждого ученика;
- повторный lesson backfill не создаёт дубли, а неизвестный номер блокирует
  транзакцию до первой записи;
- synonym reconciliation отклоняет неизвестные задачи, переход между
  занятиями, неполные/невзаимные множества и две задачи одной группы;
- неизвестная группа блокирует всю транзакцию;
- существующий или находящийся вне `.runtime/phase11-rehearsal` target
  отклоняется;
- focused suite: `11 passed`;
- полный Python regression PWA: `1 459 passed, 3 skipped`.

Legacy timestamps сохранены буквально как naive timestamps: timezone, которого
нет в source, не выдумывается. Исходный `user_changes_log` не меняется.

Этот инкремент не переносит содержимое занятий, письменные обсуждения или
строки синонимов. Он проверяет готовность legacy synonym identity к будущему
логическому backfill после появления подтверждённых problem revisions; эти
операции остаются следующими независимыми срезами Phase 11.
